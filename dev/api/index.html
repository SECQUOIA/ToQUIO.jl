Optimizer

ToQUIO.Optimizer

Optimizer{T,O<:Maybe{MOI.AbstractOptimizer}} <: MOI.AbstractOptimizer

Main optimizer type that handles reformulation and optional solving.

Type Parameters:

  • T: Numeric type for the optimization (e.g., Float64, BigFloat)
  • O: Type of the inner optimizer (or Nothing)

Constructors:

Optimizer{T}(inner = nothing) where {T}

Creates an optimizer with specified numeric type.

Arguments:

  • inner: Optional callable that returns a MOI-compatible optimizer for solving the QUIO problem

Default Constructor:

Optimizer(args...; kws...) = Optimizer{Float64}(args...; kws...)

Uses Float64 as the default numeric type.

Examples:

# Reformulation only
opt = ToQUIO.Optimizer()

# With Float64 (explicit)
opt = ToQUIO.Optimizer{Float64}()

# With a backend solver
opt = ToQUIO.Optimizer(() -> SomeSolver.Optimizer())

# With BigFloat for high precision
opt = ToQUIO.Optimizer{BigFloat}()

Fields:

  • inner::O: The inner optimizer instance (or nothing)
  • source_model::Maybe{MOI.ModelLike}: The original problem model
  • target_model::Maybe{QUIOModel}: The reformulated QUIO model
  • data::Dict{Symbol,Any}: Reformulation metadata

Reformulation Functions

to_quio

to_quio(::Type{T}, varmap::Function, conmap::Function, source::MOI.ModelLike; ϵ = one(T)) where {T}

Core function that performs the QUIO reformulation.

Arguments:

  • T: Numeric type for the reformulation
  • varmap: Function mapping VariableIndex to Int (variable position)
  • conmap: Function mapping ConstraintIndex to Int (constraint position)
  • source: Source MOI model to reformulate
  • ϵ: Penalty coefficient adjustment (default: 1.0)

Returns:

  • target::QUIOModel{T}: Reformulated QUIO model
  • data::Dict{Symbol,Any}: Dictionary containing:
    • :n: Problem dimension (number of variables including slacks)
    • :Q: Quadratic term matrix
    • :L: Linear term vector
    • :c: Constant term
    • :D: Diagonal penalty matrix used in the target objective, including the objective-sense sign
    • :rho: Selected positive penalty coefficients before applying the objective-sense sign
    • :rho_auto: Automatic sufficient positive penalty coefficients
    • :penalty_hints: User-provided penalty hints, or nothing for automatic penalties
    • :penalty_constraints: Source constraint indices corresponding to :rho, :rho_auto, and :penalty_hints, ordered as equalities, less-than inequalities, then greater-than inequalities
    • :l: Lower bounds vector
    • :u: Upper bounds vector

MathOptInterface 1.11 or later is required for source distance evaluation.

Input validation:

  • Direct source models must implement MOI.ListOfConstraintTypesPresent. Unsupported types, including scalar affine functions in MOI.Interval, are rejected with ArgumentError rather than silently omitted.
  • Every source variable must have finite lower and upper bounds and be marked MOI.Integer or MOI.ZeroOne.
  • Affine constraint coefficients and right-hand sides must be integer-valued.
  • Equality and inequality rows must be feasible within the variable bounds.
  • Equality rows must also pass the integer divisibility check for integer assignments.
  • Custom ConstraintPenaltyHint values must be finite and positive.

Mathematical Formulation:

The reformulation converts:

minimize    f(x)
subject to  A_eq x = b_eq
            A_le x ≤ b_le
            A_ge x ≥ b_ge
            l ≤ x ≤ u
            x ∈ ℤⁿ

Into:

minimize    z' Q z + L' z + c
subject to  l ≤ z ≤ u
            z ∈ ℤᵐ

Where z = [x; s] includes original variables x and slack variables s.

Example:

using MathOptInterface
const MOI = MathOptInterface

# Create a simple model
model = MOI.Utilities.Model{Float64}()
x = MOI.add_variable(model)
MOI.add_constraint(model, x, MOI.Interval(0.0, 10.0))
MOI.add_constraint(model, x, MOI.Integer())
MOI.set(model, MOI.ObjectiveFunction{MOI.ScalarAffineFunction{Float64}}(),
        MOI.ScalarAffineFunction([MOI.ScalarAffineTerm(1.0, x)], 0.0))
MOI.set(model, MOI.ObjectiveSense(), MOI.MIN_SENSE)

# Reformulate
target, data = ToQUIO.to_quio(Float64, vi -> vi.value, ci -> ci.value, model)

# Access reformulation data
Q = data[:Q]  # Quadratic terms
L = data[:L]  # Linear terms
c = data[:c]  # Constant

Custom Attributes

ConstraintPenaltyHint

struct ConstraintPenaltyHint <: MOI.AbstractConstraintAttribute end

Allows users to specify custom penalty coefficients for constraints. Hints must be finite and positive. They override the automatic sufficient coefficient, so small hints are treated as heuristic values and may not preserve equivalence to the constrained source problem. ToQUIO emits a warning when a hint is below the automatic sufficient coefficient.

Usage:

using JuMP, ToQUIO
using MathOptInterface
const MOI = MathOptInterface

optimizer = ToQUIO.Optimizer()
model = Model(() -> optimizer)
@variable(model, 0 <= x <= 10, Int)
@constraint(model, con, x >= 1)

# Set custom penalty
MOI.set(backend(model), ToQUIO.ConstraintPenaltyHint(), index(con), 100.0)

Automatic Penalty Controls

See Penalty tuning for executable inspection/sweep examples, hint precedence and warning semantics.

ToQUIO.PenaltyOffset — Type
PenaltyOffset()

Global positive additive margin for automatic penalties, default one(T). For an unhinted constraint, the applied magnitude is PenaltyScale() * (Δ_bound / ε^2 + PenaltyOffset()). Exact ConstraintPenaltyHint values bypass both controls. Set through MOI.set or the Optimizer(; penalty_offset=...) keyword. Direct to_quio calls use the existing ϵ keyword for this margin. Controls persist across MOI.empty! and affect the next reformulation; they do not rewrite a previous result.

source
ToQUIO.PenaltyScale — Type
PenaltyScale()

Global finite positive multiplier for automatic penalties, default one(T). Set with MOI.set(optimizer, PenaltyScale(), scale), the optimizer's penalty_scale keyword, or to_quio(...; penalty_scale=scale). Explicit per-constraint ConstraintPenaltyHint values remain exact and unscaled. Values below 1 may lose constrained-problem equivalence and emit a warning when the applied penalty is below the unscaled sufficient value.

source
ToQUIO.AppliedPenalty — Type
AppliedPenalty()

Read the positive penalty magnitude used for a source scalar affine equality or inequality in the most recent reformulation, if it succeeded. A failed later reformulation invalidates this query. Available without a solver backend through raw MOI.get; JuMP's high-level result getter checks solver termination status, so use MOI.get(backend(model), AppliedPenalty(), index(con)) in reformulation-only mode. Maximization subtracts this magnitude in the objective. Changing controls affects the next reformulation, not this query's recorded value.

source

For an unhinted constraint, ToQUIO applies scale * (Δ_bound / ε^2 + offset). Defaults are offset = 1 and scale = 1, reproducing the existing objective exactly. A ConstraintPenaltyHint remains an exact per-constraint magnitude and bypasses both controls. ToQUIO uses the same control names as ToQUBO but keeps its own squared-residual penalty formula. The upstream design references are ToQUBO penalty PR #143, feasibility PR #146, and metadata PR #133. ToQUIO's native integer/slack domains, composed encoding maps, applied-penalty inspection and explicit source-feasibility checks are implemented independently; these references do not introduce a ToQUBO runtime dependency.

optimizer = ToQUIO.Optimizer(; penalty_offset = 1.0, penalty_scale = 1.0)
MOI.set(optimizer, ToQUIO.PenaltyScale(), 2.0)
MOI.optimize!(optimizer, source)
MOI.get(optimizer, ToQUIO.AppliedPenalty(), constraint_index)

source and constraint_index refer to the supported MOI source model and an affine constraint index. Setting a control changes the next reformulation; applied-penalty queries and snapshots retain the values from the last one. For a JuMP model without a backend solver, query the compiled value through MOI.get(backend(model), ToQUIO.AppliedPenalty(), index(con)) after optimize!. JuMP's high-level get_attribute(con, ...) result path requires a solver status other than OPTIMIZE_NOT_CALLED, which reformulation-only mode does not provide. A failed new reformulation invalidates the current applied-penalty query. Use nothing with either control attribute to reset its default. Global controls persist across MOI.empty!; computed penalties do not. Offset and scale must be finite positive real values representable in the optimizer's numeric type. Invalid controls and overflowing target coefficients are rejected.

Direct calls keep the existing additive ϵ keyword and add penalty_scale:

target, data = ToQUIO.to_quio(
    Float64, varmap, conmap, source; ϵ = 1.0, penalty_scale = 2.0,
)

:rho_auto records the unscaled automatic value with the chosen offset; :rho records the actual scaled or hinted magnitude. Maximization subtracts the applied magnitude in the objective, while AppliedPenalty() returns its positive value. Scales below 1 can weaken feasibility protection and warn when the applied value falls below the unscaled sufficient coefficient. Existing low-hint warnings retain their meaning; a hint is compared to that unscaled reference even when a global scale is set. Global-scale warnings are aggregated once per equality/inequality kind with the affected row count, while warnings for individual low hints remain per constraint.

Reformulation Metadata and Projection

These helpers accept the dictionary returned by to_quio or an Optimizer after reformulation. Variable-list helpers return copies. The metadata snapshot can also be saved with a JSON serializer and used for projection without keeping the MOI model alive.

ToQUIO.reformulation_metadata — Function
reformulation_metadata(data_or_optimizer)

Return a fresh, string-keyed metadata snapshot for a completed QUIO reformulation. Native schema version 1 records source and full target variable ordering, affine source projections, target bounds, slack ownership, constraint canonicalization, and automatic/applied penalties. Matrices remain in the raw data dictionary. Numbers retain their integer or floating-point type and must be finite; use a JSON serializer supporting that numeric type (e.g. BigFloat). Optional encodings use schema version 2: target order/bounds and source expansions refer to encoded digits, nativevariables records each coordinate's affine map and slack ownership, and nativereformulation contains the complete version 1 snapshot with the unchanged penalties. The raw legacy keys remain native.

The returned snapshot can be passed to project_original_state, original_variables, and auxiliary_variables. Projection does not check feasibility, validate slack consistency, round values, or repair a sample. An optimizer must have been reformulated with optimize! first.

source
ToQUIO.original_variables — Function
original_variables(data_or_optimizer_or_metadata)

Return source variables in source-model order. Raw data and optimizers return MOI.VariableIndex values; serialized metadata returns integer source IDs. The returned vector is a copy.

source
ToQUIO.auxiliary_variables — Function
auxiliary_variables(data_or_optimizer_or_metadata)

Return target auxiliaries: native slacks for schema 1, or every encoded digit owned by a generated slack for schema 2. Fixed slacks need no encoded digit. Raw data and optimizers return MOI.VariableIndex values; serialized metadata returns integer target IDs. The returned vector is a copy.

source
ToQUIO.project_original_state — Function
project_original_state(data_or_optimizer_or_metadata, state::AbstractVector)

Project a full target state, in target_variable_order (native [x; s] order or encoded digit order), to a dictionary of source values. Keys are MOI.VariableIndex for raw data or an optimizer, and integer source IDs for serialized metadata. The vector length must match the full target dimension and values must be finite real numbers. Projection preserves input precision and does not round, check feasibility or repair slacks. Serialized affine expansion terms use one-based target positions, not variable IDs. Optional encodings compose native and encoded maps; all fixed source values are restored. Native coordinates can be read with projectnativestate.

source

For example, this reformulation introduces one integer slack for x <= 2:

using ToQUIO
import MathOptInterface as MOI

source = MOI.Utilities.Model{Float64}()
x = MOI.add_variable(source)
MOI.add_constraint(source, x, MOI.Interval(0.0, 3.0))
MOI.add_constraint(source, x, MOI.Integer())
f = MOI.ScalarAffineFunction([MOI.ScalarAffineTerm(1.0, x)], 0.0)
MOI.set(source, MOI.ObjectiveSense(), MOI.MIN_SENSE)
MOI.set(source, MOI.ObjectiveFunction{typeof(f)}(), f)
MOI.add_constraint(source, f, MOI.LessThan(2.0))

optimizer = ToQUIO.Optimizer()
MOI.optimize!(optimizer, source) # Reformulation only; no backend is required.
metadata = reformulation_metadata(optimizer)
original_variables(optimizer)  # MOI.VariableIndex[MOI.VariableIndex(1)]
auxiliary_variables(metadata)  # [2]
project_original_state(optimizer, [1, 1]) # Dict(x => 1)
project_original_state(metadata, [1, 1])  # Dict(1 => 1), using source IDs

Native schema version 1 is a string-keyed dictionary with the following fields:

FieldMeaning
schema_version, packageSchema version and producing package name/version
source_variable_orderOriginal source IDs in source-model order
target_variable_orderFull target IDs in state-vector order, including slacks
target_lower_bounds, target_upper_boundsBounds aligned with the full target order
original_variablesSource IDs and affine projection expansions
auxiliary_variables, slack_variablesSlack IDs, target positions and typed source-constraint identities
constraint_encodingsPenalized affine constraints in equality, <=, then >= order, with source/canonical relations, row multipliers, slack positions and automatic/applied/hinted penalties
penalty_controlsOffset and scale used at compilation; optional in older v1 snapshots
guaranteesExplicit projection, feasibility-check and repair boundaries

Constraint identities use fully qualified, context-independent function and set type strings (for example MathOptInterface.LessThan{Core.Float64}): a numeric MOI constraint ID alone is not unique across constraint types. A >= row is negated to <= before introducing its slack; metadata records its row multiplier -1. Bounds and integer-domain constraints are represented by target bounds and the native QUIO domain, rather than included in the penalized-constraint list.

Each source expansion has kind = "affine", an offset, and terms containing a target_position and coefficient. Positions are one-based state-vector positions, independent of MOI variable IDs. Native reformulation uses one term with coefficient 1 and offset 0; the format permits later multi-digit affine projections without changing the legacy one-to-one raw mapping. Optional integer encodings use schema version 2 with composed source maps, encoded target order and a nested complete native snapshot; see Integer Encoding.

Metadata contains finite integer or floating-point numbers, strings, booleans, nothing, vectors and string-keyed dictionaries. Numeric precision is retained; the chosen JSON serializer/reader must support the number type when using arbitrary precision. Matrices Q, L, D and c stay in the internal data dictionary and are excluded from the stable snapshot.

Projection accepts a full target vector, including all slacks, and rejects a wrong length or nonfinite/non-real values. It preserves fractional samples and does not certify source feasibility, check target-domain/slack consistency, or repair auxiliaries. For example, projecting [1.5, -10] yields x = 1.5 even though that sample violates the target's integer and slack domains. Unknown schema versions and malformed document fields are rejected with ArgumentError. IDs, positions and numeric expansion fields reject booleans. A failed new reformulation invalidates the optimizer's current metadata; a previously retained raw dictionary or metadata snapshot remains usable across that failed call. MOI.empty!(optimizer) clears the live raw dictionary and models; save a returned metadata snapshot when a record must survive this reset. Existing raw keys such as :target_variables (original-variable targets only), :rho and :Q keep their previous meaning; :quio_variables adds the full target order and :slack_constraints adds ownership. :source_constraints stores copied (index, func, set) named tuples for source feasibility evaluation. These MOI functions/sets stay in raw data and are not part of the portable projection snapshot. With optional encoding, those raw keys continue to describe native coordinates; :encoded_variables and :encoded_Q, :encoded_L, :encoded_c describe the actual backend target. auxiliary_variables returns actual slack-owned target digits, while project_native_state restores the native coordinates.

Original Source Feasibility

Aggregate optimizer reports retain every result record, with result_index, primal_status and evaluated. Only feasible, nearly feasible, and infeasible primal points are evaluated; absent solutions, certificates and unknown statuses are skipped. feasible_fraction divides by primal_point_count, not result_count, and is nothing if there are no points. Requesting a nonpoint result explicitly raises ArgumentError. Direct state calls have no backend status and evaluate the supplied values.

ToQUIO.ConstraintViolation — Type
ConstraintViolation

An original source constraint whose distance to its set exceeds the requested tolerance. Fields are constraint, function_type, set_type, value, violation, raw_residual, and source_values (the involved source variables). violation is a nonnegative distance in the constraint's native units; raw_residual retains its sign where applicable. No values are rounded or repaired.

source
ToQUIO.violations — Function
violations(data_or_optimizer, state::AbstractVector; atol=1e-6)
violations(optimizer; result=1, atol=1e-6)

Return ConstraintViolation entries for original source constraints whose distance to the set exceeds atol. Evaluate the captured source model on projected original variables, including bounds, integrality and binary domains. The explicit state is in full target order, including slacks. Optimizer results are read through the target-to-backend index map at the selected result index. Fractional samples are not rounded. This is a tolerance-based check, not a certificate of optimality. Serialized projection metadata alone does not contain the source functions needed for this analysis.

source
ToQUIO.is_feasible — Function
is_feasible(data_or_optimizer, state::AbstractVector; atol=1e-6)
is_feasible(optimizer; result=1, atol=1e-6)

Return whether violations is empty for the source model. Consistency of generated slacks is independent of original source feasibility and is not used to classify the point. No repair or rounding is performed.

source
ToQUIO.feasibility_report — Function
feasibility_report(data_or_optimizer, state::AbstractVector; atol=1e-6)
feasibility_report(optimizer; result=nothing, atol=1e-6)

Return source feasibility, all per-constraint distances/residuals, projected values and optional target residuals. Optimizer result=nothing (the default) summarizes every available result; specify an index for one result. The aggregate counts result records, not read multiplicities. Only FEASIBLE_POINT, NEARLY_FEASIBLE_POINT, and INFEASIBLE_POINT records are evaluated; unavailable, certificate and unknown-status records are retained with evaluated=false. feasible_fraction uses primal_point_count as its denominator and is nothing when no points are available. Selecting a nonpoint result explicitly raises ArgumentError. Max/sum violation diagnostics use native constraint units without normalization. Source feasibility does not certify target slack consistency; target residuals remain separate and can be nonzero at a feasible source point. The source snapshot remains independent of later model edits.

source

For the reformulation-only example above, the full target order is [x, slack]:

is_feasible(optimizer, [1, 1])     # true: x <= 2, and x is integer/in bounds
violations(optimizer, [3, 0])      # source LessThan violation of magnitude 1
report = feasibility_report(optimizer, [1, 9])
report["feasible"]                # true for the source point x = 1
report["constraints"]             # target residual exposes inconsistent slack

For a solver-backed optimizer, violations(optimizer; result=2) reads that result's complete target state through the recorded backend index map. The default feasibility_report(optimizer) summarizes all result records; these counts do not include sampler read multiplicities. A report with no results has feasible_fraction = nothing. A requested missing result raises MOI.ResultIndexBoundsError.

The analysis evaluates a captured copy of the source constraints from the most recent successful reformulation. It supports source scalar affine =, <=, >=, and variable bounds, intervals, integrality and binary domains. Later edits to the caller's model do not change that snapshot; reformulate to analyze them. Direct to_quio dictionaries contain the same snapshot. Older dictionaries and serialized projection metadata without source functions cannot perform this check.

atol is a finite nonnegative absolute tolerance in each constraint's native units. Violation magnitudes and signed residuals remain unmodified in the report, including small residuals accepted by the tolerance. Max/sum diagnostics do not normalize different constraint units. Integrality checks use the actual sample values without rounding. The source-feasibility verdict is independent of target slack consistency and penalized objective energy; neither feasible samples nor a target-optimal status certify optimality for the source problem.

Type Aliases

For convenience and readability, ToQUIO defines several type aliases to shorten commonly-used MathOptInterface types. These aliases make the code more concise while maintaining type safety and enable type-generic programming across different numeric types.

const MOIU    = MOI.Utilities              # MOI utility functions
const VI      = MOI.VariableIndex          # Variable index type
const CI{F,S} = MOI.ConstraintIndex{F,S}   # Constraint index (function F in set S)
const EQ{T}   = MOI.EqualTo{T}             # Equality constraint set
const LT{T}   = MOI.LessThan{T}            # Less-than constraint set
const GT{T}   = MOI.GreaterThan{T}         # Greater-than constraint set
const SAF{T}  = MOI.ScalarAffineFunction{T}   # Affine (linear) function
const SQF{T}  = MOI.ScalarQuadraticFunction{T} # Quadratic function
const Maybe{T} = Union{T,Nothing}          # Optional type (value or nothing)

These aliases are particularly useful when writing type signatures for functions that handle different constraint and function types, reducing verbosity while maintaining full type information for Julia's type system and multiple dispatch.

QUIOModel

QUIOModel{T}

A MOI model type specifically for QUIO problems, created using MOI.Utilities.@model.

Supported Features:

  • Scalar sets: EqualTo, LessThan, GreaterThan, Interval
  • Vector sets: Zeros, Nonnegatives, Nonpositives
  • Scalar functions: ScalarAffineFunction, ScalarQuadraticFunction
  • Vector functions: VectorOfVariables, VectorAffineFunction
  • Variable constraints: Integer, ZeroOne

Usage:

model = QUIOModel{Float64}()
x = MOI.add_variable(model)
MOI.add_constraint(model, x, MOI.Interval(0.0, 10.0))
MOI.add_constraint(model, x, MOI.Integer())
# ... set objective, etc.

Supported Constraint Types

The Optimizer supports the following constraint types:

Variable Constraints:

  • VariableIndex-in-EqualTo{T}
  • VariableIndex-in-LessThan{T}
  • VariableIndex-in-GreaterThan{T}
  • VariableIndex-in-Interval{T}
  • VariableIndex-in-Integer
  • VariableIndex-in-ZeroOne

Affine Constraints:

  • ScalarAffineFunction{T}-in-EqualTo{T}
  • ScalarAffineFunction{T}-in-LessThan{T}
  • ScalarAffineFunction{T}-in-GreaterThan{T}

Supported Objective Types

  • ScalarAffineFunction{T} (linear objectives)
  • ScalarQuadraticFunction{T} (quadratic objectives)

Both minimization and maximization are supported.
